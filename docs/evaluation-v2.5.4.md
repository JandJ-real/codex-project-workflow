## 失败与观察

- T1-R1-A：mode, workflow
- 队列范围：正式发布比较只包含本候选58回合：资料各25项、路由各4项；D5/D6各5对。追加数和材料在任何本队列模型调用前固定，未继续按结果扩样。
- 执行背景：首组T1、D5、D6按预登记计划前置，以尽早发现已知故障；其余配对顺序保持。补充组只运行D5/D6，历史产物与缓存背景可能和主队列不同；两版在每个配对内使用相同条件，不将组间差异当作同条件因果比较。
- 前候选v2.5.3：完整58回合功能全部通过，但D6五对非缓存输入比值中位1.017、合计回退约24%，未达到预登记性能门槛，因此未发布。其原报告、一次由保存轨迹恢复的记录及四个原计划续跑回合均保留，未混入本轮。
- 本轮针对性变化：--sources-from只在程序内读取相关JSON产物的sources[].file，完成去重、范围与数量检查后校验当前源并查询；旧values、引用全文和命令不会被回放到模型。它用于减少先读旧答案再查询的额外模型往返；是否采用和实际收益仍由本轮轨迹与用量判定。
- 未发布候选2.5.0：此前50回合包含主机计时跳变及超时，原始记录保留，无法还原完整暂停时间，不估计扣除。该候选未发布，也未混入本队列。
- 未发布候选2.5.1：此前完整50回合A25/25、B24/25；新版T1文字及日期正确但枚举错误，且D5三对非缓存输入比值中位1.072回退，未发布。未执行的额外8回合协议保留并标记not_run，不计模型样本。
- v2.5.2服务中断试验：先行队列有4个结果记录，其中B两回合被serverOverloaded拒绝，另1个A回合被中断只有轨迹。容量错误2、明确重试0，原始用量保留；未与本完整队列混合，也未补零。
- v2.5.2来源恢复失败：重启服务后的队列完成22回合，D6-R1-B误选无关扫描材料，将两个存在的字段误报unknown，伴随额外工具探测和token回退；因此停止该候选，另1个A回合中断无result。v2.5.3明确恢复相关产物sources中的实际文件集合，本队列先测已知失败点。
- 重复校验边界：对已经有效的缓存，--batch共享当前进程中已校验的语料，确定性测试验证每份源文件只做一次内容哈希。首次转换前后仍校验源内容，独立CLI调用仍重新哈希以检测静默更新。手写哈希与完整缓存打印线索为零，不代表所有跨调用重复校验或额外查询都消失；原始哈希总数不等于冗余次数。
- 前轮分类器修正沿用：沿用已回归验证的命令分类：显式数组行区间输出不视为整份缓存打印，全量变量输出仍视为全文。对两版统一处理，额外读取的工具文字、token和耗时全部保留。
- 性能解释：总输入、缓存输入和非缓存输入分别呈现；提供方提示缓存与负载未受控。配对中位改善不等于每次调用都改善，也不能证明跨模型或真实未知资料的稳定收益。

## 限制

- 主要资料场景使用三套独立变化的合成材料；重点场景预登记的追加次数见分场景表，仍不能代表所有真实项目。
- 只测试一个模型和推理设置；所有任务显式调用本地 Skill，没有测试隐式触发率。
- Python I/O 记录不是系统级监控；其他源读取同时包含解析和普通读取。
- 路由探针使用离线证据包，没有测试真实联网调研质量。
- 提供方提示缓存与日志外网络延迟未受控。
- 只测试扫描页缺口披露，没有评价 OCR 或复杂视觉理解质量。

BM25和中文切分仍属于词法检索，不保证语义召回；图像、音视频和专业二进制依赖适用读取器的结果登记，内置转换器没有覆盖全部格式。
云端模型回归需仓库显式配置凭据和启用开关；缺失时不得声称已执行。
