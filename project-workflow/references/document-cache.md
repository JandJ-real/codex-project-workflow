# PDF 与 Word 正文缓存

目标是避免重复调用格式读取技能、重复解析二进制文件和重复把整篇内容送入上下文。正文缓存保存可提取内容，项目摘要保存理解与决定，两者分工不同。

## 首次处理

1. 明确原始输入的有效版本。存在有效缓存则先复用；新会话、输入发生变化或准备使用未确认的版本时检查一次即可，同一任务不反复预检。
2. 若格式技能已经提取正文，把这份正文直接保存为 Markdown；用下方 `--from-markdown` 登记，不为生成缓存重新读取原件。不要用 AI 的简短总结冒充完整提取正文。
3. 尚未提取的普通文本 PDF／DOCX，按下方接口运行随附的 `scripts/document_cache.py`；不以通读脚本实现作为例行前置。只有接口不适用、运行报错或需要修改工具时才检查相关实现。它生成 Markdown 与同名 `.meta.json`，输出路径和提取状态；之后检索完成任务需要的正文片段。
4. 缓存工具返回 `created`／`reused` 时，已经检查来源指纹与缓存状态；若 `needs_review=false`，直接检索本次所需正文与页／段定位，不再完整打印元数据或另写相同的指纹检查。只有需要具体缺口、版本对照、旧定位映射或错误诊断时，才读取对应元数据字段。`text_extracted_unverified` 和通用版式警告表示能力边界，不单独触发重新解析。仍须核对关键内容、语义与定位；扫描页、公式、表格、错序或冲突影响结论时定向核对原件。不要用相同解析器重提全文来验证自身遗漏；一次问答不额外建状态文件。

## 命令

以下路径相对于技能根目录。使用能访问 pypdf 与 python-docx 的 Python；在 Codex 优先采用工作区依赖加载器返回的运行时。

```text
python "<skill>/scripts/document_cache.py" "原始资料.pdf" --cache-dir ".ai-cache/documents"
python "<skill>/scripts/document_cache.py" "原始资料.docx" --cache-dir ".ai-cache/documents"
python "<skill>/scripts/document_cache.py" "已读取的资料.pdf" --cache-dir ".ai-cache/documents" --from-markdown "首次提取正文.md"
```

普通缓存命中只检查来源路径、文件大小、修改时间、文件标识以及缓存产物状态，不重新解析文件，不计算原文内容哈希。`created` 表示新建或重建；`reused` 表示复用；`error` 必须处理。`quality` 是提取状态，绝不等于语义或版式验证通过。

输入路径已经明确时，直接运行上述接口，使用返回的缓存路径与结构信息；不为再次发现这些已知路径重复枚举项目、技能脚本或缓存目录。能合并为一轮工具调用的独立文件检查可合并执行，分别处理各文件状态；不要把一个文件的成功当作全部成功。

若怀疑传输或外部修改保留了相同元数据，或更换了提取方法，显式添加 `--refresh`。字节一致性本身是验收要求时，才另行采用内容校验。原始输入不会被改写。

## 后续读取

- 先按本次问题里的具体字段、专有名或短语搜索，取得命中和附近定位标记，再按需要扩大上下文。不要把 `validation|model|block|PDF page` 等通用词或所有位置标记并入内容搜索；这会命中大量无关正文。匹配太多时先缩窄词，不连续重输近似全文。
- 使用目录加文件过滤，避免依赖 shell 展开通配符。以下写法适用于 Windows PowerShell，也可用于常见 Unix shell：

  ```text
  rg -n -F -e "latency_limit_ms" -e "split_seed" -g "*.md" ".ai-cache/documents"
  ```

  示例字段替换为当前问题的关键词；命中内容不足时，再取该命中附近的页／段标记与必要文字。搜索结果是候选证据，仍需核对有效版本、语义与相关缺口。
- PDF 的 `PDF page N` 是从1开始的物理页序。新生成的 DOCX 缓存保留 `block NNNN`，另有 `paragraph NNNN` 与 `table NNNN`；CLI及元数据的 `structure` 提供顶层段落／表格数量。段落号只数正文顶层段落，含标题和空段，不数表格及表内段落；表格用表号／块号定位，不冒充渲染页码。
- 有效缓存已明确段落编号且无相关提取疑点时，直接据此引用，不为重新数段落再打开 Word。旧缓存只有块号时，不假定块号等于段落号；可按任务允许引用块号。必须给段落号且映射不明时，定向核对一次相关结构，或仅对该 DOCX 用 `--refresh` 生成增强定位，不为缺少新字段批量刷新旧缓存或无关 PDF。
- 在状态中保留“原件 → 缓存路径 → 提取状态／已核对位置／剩余缺口”；详细正文留在缓存。大量文件按资料索引检索，不把全文塞进 PROJECT.md。
- 源文件改变、缓存丢失或损坏时重建受影响文件。暂时提取失败时不把旧缓存标为当前有效，不重复尝试同一失败方法。
- 补充的 OCR／人工核对记录可单独存放并关联源版本；缓存生成器会重建自己的文件，不把人工批注写入其自动正文。

## 能力边界与升级路径

- 内置工具默认支持文本 PDF 和 DOCX 正文、标题、表格；DOCX 表格的首行只是 Markdown 表达所需，不保证原文语义上有表头。脚注、批注、修订、图像和原生公式不当作已完整提取。
- PDF 文本顺序、复杂表格、公式、图形与 OCR 质量不能由文本缓存保证。无文字页会标记待核对，可能是空白页或扫描页，不自动认定扫描失败。
- 老式 `.doc` 先由适用的 Word 工具提取或转换，再登记；不假装仅改扩展名就能读取。
- Microsoft MarkItDown 是可选的多格式转换来源；需要更多格式时再采用，本技能不默认安装其全部依赖或启用云端服务。复杂版式可考虑专用解析／OCR，完成后复用结果并更新缺口。
- 这里只规定技能执行时的缓存行为，不是操作系统的后台监控。首次仍需提取成本；持续节省依赖后续按片段检索。
