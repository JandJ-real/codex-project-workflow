# 输出可独立使用的完整提示词

适用于用户明确要求审阅、保存、复制、迁移或复用提示词。普通执行请求不走此模式。只要求提示词时不执行其中描述的任务。

## 生成框架

```text
目标与范围：问题、预期结果和本次允许处理的部分。
必要输入与约束：有效资料、缓存定位、硬限制和已确认选择。
交付与验收：产物、位置、格式、可判断的完成条件和必要证据。
执行边界：先提供方案／只讨论／直接完成已授权任务，以用户原话为准。
```

- 用户用口语说意图即可；从原话和有效项目上下文提取信息，简单任务合并字段，不强迫补齐无关项。
- 仅在条件成立时补充竞赛、科研、文档缓存、检查或下游结构化输出模块；模板优化参考 prompt-design.md，不复制所有模块。
- 不擅自选择模型、改变技术路线、增加任务、编造指标或加批准步骤。会改变目标或验收的缺口才澄清；可交付的未知项用明确占位符，并注明需要补什么。
- 提示词应独立可理解，不使用“同上”。执行环境可访问文件时给出有效路径；仅支持文本时纳入完成任务所需的约定和事实摘要，不暗示接收者拥有本地文件。
- 输出一条当前适用的完整提示词。用户要求保存时才按其位置写入文件；无需每次生成整套模板或另发一次模型请求。

## 边界示例

- “帮我把这些数据清理一下”是执行请求，整理必要任务信息后直接做。
- “帮我写条提示词，用来清理这批数据，先别执行”只交付提示词。
- “先聊聊怎么清理更合适”先讨论候选处理方法，不把猜测的数据规则当作修改授权。
