# 用最低正确性门槛与变更范围决定检查

目标是减少无用复查，同时尽早发现高概率、后果明显的错误。先确定本次真正可能出错的位置，再选能暴露它的检查；不把下面所有条目机械应用于每个任务。

## 按产物选择最低门槛

| 产物或改动 | 交付前需要回答的问题 | 常用的最小检查 |
| --- | --- | --- |
| 普通说明或轻量格式编辑 | 目标、关键事实和格式是否满足要求？ | 一次针对内容的核对；无关审计不运行 |
| PDF／Word 正文缓存 | 版本、定位和提取缺口是否清楚？ | 缓存状态＋相关正文片段与定位核对；具体提取疑点才定向核对原件，不重复同一方法全量解析 |
| 代码行为、数据转换或接口 | 关键路径能否运行？关键边界和输出是否正确？ | 小输入端到端运行＋相关回归／边界；修复后重跑受影响项 |
| 竞赛训练与提交产物 | 指标方向、切分、训练／验证隔离与输出格式可信吗？ | 固定验证协议、小规模训练推理；提交文件的列、ID、行数、有限值和必要范围 |
| 科研结论与实验 | 主张是否有来源？计算和比较是否可复现？ | 来源定位、配置与基线、关键计算；稳定性结论按需要增加种子或统计验证 |

项目既定 CI、测试和交付要求仍须完成；上表不用于豁免已有必要检查。对输出格式有重要约束的任务，用轻量程序检查可确定的约束，别只让模型再次口头自查。

## 追加检查的触发条件

- 改到数据划分、指标计算、预处理拟合、公共接口或缓存有效性：追加相应回归与关键边界。
- 需要长训练、大批量处理或高成本运行：先小样本跑通读取到输出的完整链路，再扩大规模。
- 引用、公式、数值或表格关系影响最终决定，且缓存有遗漏／OCR／排版歧义：定向核对原文位置，不重新渲染全套无关材料。
- 反复出现同类错误：先定位原因，为真实故障补一个能失败的回归用例；修正规则中相应的狭窄条款，不无限叠加全局检查。
- 一个检查通过不能替代另一个独立性质：文件能打开不证明数值正确，脚本运行成功不证明无数据泄漏，公共榜分数上升不证明泛化稳定。

## 复用与停止

检查记录写清对象／配置版本、运行方式、结果、证据位置。相关输入、代码和环境未变化且无新疑点时直接复用；有变化只重查受影响性质。每次复查应指出一个具体尚未排除的故障。

满足验收及最低门槛后交付，不再做没有新证据的“再检查一遍”。有错误则修复并复验；未执行、无法执行、未通过与通过分别记录。无法完成的必要检查影响完成状态，不能改写成成功。
