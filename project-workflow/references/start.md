# 启动项目与建立约定

适用于用户要求启用项目工作流、初始化协作规则，或开始需要持续跟踪的项目。先确定实际项目目录和当前请求是执行、规划还是仅讨论。

1. 复用已有项目约定、计划和状态，仅读取建立当前理解所需的内容。不要先扫描全部资料。
2. 在用户允许的文件写入范围内，适配 assets/AGENTS.template.md 为项目根目录的 AGENTS.md，适配 assets/PROJECT.template.md 为 PROJECT.md。已有同名或同用途文件时合并有效内容或建立索引，不整份覆盖。
3. 用自然输入和来源填写目标、限制、验收、执行范围与简短路线；未选定的基础方案和指标保留待确认，不伪装成批准记录。
   同时记录当前场景（竞赛／科研／一般）与调研深度；有 PDF／Word 时先按文档缓存参考持久化正文，状态只保存路径、关键理解与缺口，不复制全文。
4. 当前阶段写清交付物、允许修改、暂缓项、必要检查和改线条件。已有选型直接沿用。
5. 用户只要求先规划时，交付具体方案供选择；已授权执行明确范围时继续执行、修复和相关检查，不再增加一次“确认这份提示词”的步骤。

## 信息整理框架

```text
目标与场景：从用户原话提取问题及使用对象，判断竞赛／科研／一般。
输入：有效文件、资料、现有代码和已确认的项目事实。
范围与约束：允许研究或修改的部分，固定方案、时间和资源限制。
执行方式：先规划／只讨论／已授权范围内执行，以用户实际要求为准。
验收：已定完成标准和最低正确性门槛；影响结果的缺口给具体选项。
输出：交付物、位置和格式，优先沿用项目约定。
当前阶段：主要交付、边界、检查停止条件及改线触发条件。
```

以上是可选框架，不要求逐项输出。复杂输入按 prompt-design.md 加当前需要的条件模块，简单任务合并字段。

用户可以只说“这项目先把现有基线跑通，模型先别动，结果和配置留下来”。据此提取目标与不改模型的约束，检查已有运行说明和结果约定。不要替用户编造最终精度目标、预算或已经成功的实验结果。
